# 공통 문체

네 문서(로드맵, PoC, PRD, Design Doc)가 모두 따른다. 쓰기 전에 이 파일을 읽는다.

## 문장

- 한 문장에 사실 하나. "~한다." 또는 "~함"으로 끝낸다.
- 수식어를 쓰지 않는다(명확한, 자연스럽게, 보장, 핵심, 효과적인).
- 결정을 쓴다. 이유는 판단이 갈릴 만한 곳에만 한 줄 붙인다.
- 생각한 과정, 출처 해석("~에 따라", "~로 본다")을 줄마다 달지 않는다. 출처는 문서 앞머리에 한 번 적는다.
- 문서 자체에 대한 설명("이 문서는 ~를 근거로 썼다")을 쓰지 않는다.

## 표기

| 이렇게 | 이렇게 쓰지 않음 |
|---|---|
| `dev에`, `` `status`를 `` | `dev 에`, `` `status` 를 `` |
| 쉼표로 나열: 목록, 상세, 답변 | 목록 · 상세 · 답변 |
| 괄호나 줄바꿈 | 긴 대시 — |
| "작성자 본인" | 「작성자 본인」 |
| 표 안은 평문 | 표 안 **굵게** |

- UI 문구와 코드 식별자는 원문 그대로 백틱으로 감싼다. 원문에 대시 같은 기호가 있어도 고치지 않는다.
- 다른 절은 번호가 아니라 이름으로 가리킨다("검토한 대안 참고").
- 파일 경로와 행 번호는 본문에 쓰지 않는다. 코드는 기능 이름으로 부른다.
- 읽는 사람이 열 수 없는 것(작성자 로컬 파일, 개인 메모)은 참조하지 않는다.
- 사실은 코드, 데이터, 요구사항 문서에서 확인한 것만 쓴다. 「없다」, 「모른다」도 확인한 뒤에 쓴다.

## 표와 그림

- 비교, 기준, 대응은 표로 쓴다. 조건을 차례로 확인하는 판단은 번호 목록으로 쓴다.
- 그림은 SVG로 직접 그리고 PNG로 만든다. 자동 배치 도구(Mermaid 등)는 선이 엉켜 쓰지 않는다.
  1. 문서 옆 `images/`에 SVG를 쓴다. 글꼴은 `Apple SD Gothic Neo, Noto Sans KR, sans-serif`.
  2. `bash <플러그인>/shared/render_svg.sh images/<이름>.svg <너비> <높이>`로 PNG를 만든다.
  3. PNG를 열어 글자와 선이 겹치지 않는지 본다.
  4. 문서에 PNG와 SVG 원본 링크를 넣고, 같은 내용의 표를 바로 아래에 둔다.

## 도구

문서 공유 도구(예: Confluence, Notion)와 작업 추적 도구(예: Jira, Linear)는 팀마다 다르다. 문서에는 도구 이름 대신 역할로 쓰고, 도구에 맞춘 안내는 넘길 때 사용자에게 따로 준다.

## 점검

`python3 <플러그인>/shared/check_style.py --kind <roadmap|poc|prd|design> <문서>`가 합계 0이 될 때까지 고친다.
